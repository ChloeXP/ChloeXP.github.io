01 · PURPOSE

Why revisit the project

The course project adapted a DistilBERT notebook (English news) to French news. The dataset (diverse_french_news) has titles, descriptions, bodies and URLs, but no topic labels. The first version labelled articles with a keyword rule and reported 74.8% accuracy for CamemBERT on 373 test articles.

Reviewing it raised three doubts: were the labels right, was a single run on 373 articles reliable, and did the report match the notebook? The revision answers one question: what actually drives performance on this task — the labels, the model, the input, or the training recipe?

03 · STEPS

What I did, step by step

STEP 1 · DIAGNOSE
Did
Parsed every Le Monde URL and re-ran the original keyword rule on all articles.
Why
The URL path holds the section chosen by the editors, a far better label source than hand-written keywords.
Result
91 sections found. The keyword rule was badly broken: 71 of 349 keywords contained capitals and could never match the lower-cased text, 14% of articles matched no keyword and silently defaulted to Monde, and overall it agreed with the editors on only 38.8% of articles (macro-F1 0.322 as a classifier).
STEP 2 · REBUILD LABELS
Did
Dropped format sections (opinion, fact-checking, obituaries, magazines), mapped the rest to 10 topics, then re-split 80/10/10 stratified by class.
Why
Opinion pages or obituaries describe a format, not a topic. Three original classes (Météo, Jeux, Europe) do not exist as sections at Le Monde.
Result
13,071 articles, imbalance 6:1 instead of 22:1, and a test set of 1,308 articles instead of 373.
STEP 3 · HUMAN BASELINE
Did
Blind-annotated 99 test articles from title and description, then reviewed the disagreements with the answer visible.
Why
To know how ambiguous the task is before reading model scores.
Result
A French-speaking reader agrees with the editors only 50.5% of the time (63% when choosing a single class). The non-blind review accepted all 49 editor labels, an anchoring effect, so only the blind labels were kept.
STEP 4 · TRAINING PIPELINE
Did
Title and description passed as a sentence pair, dynamic padding, warm-up and decay, class weights, early stopping on validation macro-F1, fp16, full seeding — all behind one run_experiment(config) function, smoke-tested locally with a tiny model before using GPU time.
Why
The first version concatenated a literal "[SEP]" string, padded to 256 tokens for ~65-token inputs and kept the last epoch.
Result
One reusable function for every experiment.
STEP 5 · ROBUSTNESS & ABLATION
Did
Five seeds of the same model; the original training recipe re-run on the new data; bootstrap, paired-bootstrap and McNemar tools.
Why
To separate signal from noise, and to see how much of the improvement came from the new recipe.
Result
Seeds move macro-F1 by ±0.3 pt, the test sample by ±2 pts. The improved recipe gave +0.07 pt (not significant): the jump from 0.72 to 0.82 came from the data, not from training tricks.
STEP 6 · MODELS & DATA
Did
Compared 11 encoders (English, multilingual, French; 2019–2025; base and large), three input lengths and four training-set sizes, 3 seeds each.
Why
With the recipe ruled out, gains could only come from a better encoder or more information.
Result
Reading the body is the only significant gain (+2.6 pts). Good French models and large models are all within ±1 pt of each other.
STEP 7 · DELIVERABLES
Did
A final notebook that rebuilds every table and figure from the 61 saved run logs in about a minute on CPU, plus a written report.
Why
The first report contained numbers that could not be found in the notebook.
Result
Every reported number is traceable to one source.

Reading the results

  • Pre-training language matters: English → multilingual → French gives 0.737 → 0.777 → ≈ 0.82.
  • Size and recency matter much less: from CamemBERT (2020) to CamemBERTv2 (2024) and ModernCamemBERT (2025), and the large models, all are within ±1 pt. CamemBERTv2 matches XLM-R-large with 5× fewer parameters and ~4× less training time.
  • The ceiling is editorial: Éducation and Société stay around 0.6 for every model, because education stories are filed in both sections.
  • Covid shortcut: 2020–2022 data; Covid articles are ~10 pts less accurate and their errors drift towards Planète & Santé.
What the model reads > which model reads it > how it is trained.
05 · PROBLEMS & FIXES

What went wrong, and how I fixed it

LABELS

The ground truth was wrong

The first version's keyword rule disagreed with the editors on 61% of articles, so the 74.8% accuracy measured how well a model imitates the rule.

Fix: labels rebuilt from the editorial section in the URL, format sections dropped, classes redefined from the data. This alone moved macro-F1 from 0.72 to 0.82.

TOKENIZER

A silent tokenizer swap

CamemBERTv2 and CamemBERTaV2, the strongest French base models in their authors' benchmarks, scored 0.38. With transformers 5, AutoTokenizer loaded an English byte-level tokenizer that cut French words into letters (6.46 tokens per word).

Fix: load tokenizer.json directly (1.33 tokens per word), scores back to 0.824 / 0.817, plus an automatic tokens-per-word check that stops a run in seconds before any GPU time is spent.

EVALUATION

Noise that looks like progress

A single run scored 0.8235, higher than every later seed; most model differences were under 1 pt, while resampling the test set moves scores by ±2 pts.

Fix: 3–5 seeds per setting and paired tests on the same articles. The ablation then showed the improved training recipe was worth +0.07 pt — a negative result worth reporting.

06 · NEXT STEPS

Improvement directions

  • Best trade-off model: CamemBERTv2 with the body text; longer training for CamemBERTaV2, which had not converged after 6 epochs.
  • Better labels for mixed topics: multi-label or hierarchical classes for articles that are, for example, both Politique and Covid.
  • Robustness over time: a temporal test split (post-2022 articles) and a second newspaper to test cross-source generalisation.
  • From notebook to service: experiment tracking with MLflow from the 61 run logs, a FastAPI + Docker inference API, CI with GitHub Actions, and a public demo.
